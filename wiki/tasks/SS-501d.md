# `add` command — install during validation flow (1.2.3)

## Summary

Implements the special flow when the repo is known, the commit hash differs, AND validation is actively running (`repoValidationStatus: "in progress"`). The CLI calls `scanRepository` (SS-301) and receives a response with `known: true`, different commit hash, and `repoValidationStatus: "in progress"` ([FR-CLI1d](../requirements.md#fr-cli1d)). Install directly from the backend response without any DB writes. No telemetry call, no status changes — validation is actively running, so we don't interfere with it. Proceed directly to SS-502 (platform selection) and SS-503 (file extraction/write).

## Unit test requirements

- Given a scan response with `known: true`, different commit hash, and `repoValidationStatus: "in progress"`, the command proceeds to install without calling telemetry.
- No DB writes occur (no status changes, no install count increments).
- The command displays a message informing the user that validation is in progress and the install is proceeding without updating the registry.
- File content is extracted and written from the backend response.

## Integration test requirements

- Running the command against a mocked `scanRepository` HTTP response (with `known: true`, different commit, status `"in progress"`) end to end:
  - Displays "validation in progress" message
  - Skips telemetry call entirely
  - Proceeds directly to platform selection and file write
- Verify that no HTTP call is made to the telemetry endpoint.
- Verify that file content from backend response is available for SS-503's extraction step.
