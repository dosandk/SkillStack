# `add` command — different commit flow (1.2.2)

## Summary

Implements the reinstall flow when the repo is known, the commit hash differs, AND the repo status is not `"in progress"`. The CLI calls `scanRepository` (SS-301) and receives a response with `known: true`, different commit hash, and `repoValidationStatus` not `"in progress"`. Notify the user that a new version is available ([FR-CLI1c](../requirements.md#fr-cli1c)). If the user chooses to proceed: call the telemetry endpoint (SS-504) with update logic to update the commit hash in Firestore, diff skills (delete removed, add new, increment existing), recalculate the aggregated install count, and set the repo + all skills to `"pending"`. Then proceed to SS-502 (platform selection) and SS-503 (file extraction/write).

## Unit test requirements

- Given a scan response with `known: true`, different commit hash, and status not `"in progress"`, the command notifies the user of the new version.
- User is prompted whether to proceed with the update.
- If user declines, the command exits without calling telemetry or installing files.
- If user proceeds, telemetry is called with update=true and the new commit hash.
- Telemetry performs skill diff: removes deleted skills, adds new skills, increments existing skills.
- Repo and all skills are set to `"pending"` status in the telemetry call.
- Aggregated install count is recalculated.

## Integration test requirements

- Running the command against a mocked `scanRepository` HTTP response (with `known: true`, different commit, status not `"in progress"`) end to end:
  - Displays "new version available" message
  - Prompts user for confirmation
  - Calls telemetry with update logic
  - Proceeds to platform selection and file write
- Verify that the telemetry endpoint receives the correct skill diff data.
- Verify that file content from backend response is available for SS-503's extraction step.
