# `add` command — first install flow (1.1)

## Summary

Implements the first install flow when a repo is unknown to the backend (`known: false`). The CLI calls `scanRepository` (SS-301) and receives a response indicating the repo is not in the registry. Warn the user that the repo is unvalidated and ask for confirmation ([FR-CLI5](../requirements.md#fr-cli5), [FR-CLI1a](../requirements.md#fr-cli1a)). If `--skill` was omitted, list every discovered skill and let the user pick one or more ([FR-CLI4](../requirements.md#fr-cli4)). After selection/confirmation, call the telemetry endpoint (SS-504) to create the repo + skills in Firestore with `"pending"` status, set install counts, and calculate the aggregated install count. Then proceed to SS-502 (platform selection) and SS-503 (file extraction/write).

## Unit test requirements

- Given a scan response with `known: false`, the command prints the unvalidated warning and halts until the user confirms.
- If `--skill` was omitted, the command presents every discovered skill for selection (multi-select).
- If `--skill` matches a discovered skill, the command proceeds directly without a selection prompt.
- If `--skill` matches nothing discovered, the command reports no match and exits without installing.
- After user confirmation and selection, the telemetry endpoint is called with the selected skills.
- If the user declines the unvalidated warning, the command exits without calling telemetry or installing files.

## Integration test requirements

- Running the command against a mocked `scanRepository` HTTP response (with `known: false` and file content) end to end:
  - Displays the unvalidated warning
  - Presents skill selection if `--skill` not provided
  - Calls telemetry with correct repo/skill data
  - Proceeds to platform selection and file write
- Verify that file content from backend response is available for SS-503's extraction step.
