# `add` command — same commit flow (1.2.1)

## Summary

Implements the reinstall flow when the repo is known and the commit hash matches what's stored. The CLI calls `scanRepository` (SS-301) and receives a response with `known: true` and matching commit hash. Show skills with their existing validation statuses (`valid: boolean` from Firestore) ([FR-CLI1b](../requirements.md#fr-cli1b)). User selects which skills to install. Call the telemetry endpoint (SS-504) to increment install counts for the selected skills (sets `"pending"` only for newly installed skills that weren't previously installed). Then proceed to SS-502 (platform selection) and SS-503 (file extraction/write).

## Unit test requirements

- Given a scan response with `known: true` and matching commit hash, the command displays skills with their validation statuses (`"validated"`, `"failed"`, `"pending"`).
- User can select which skills to install from the list.
- If `--skill` matches a discovered skill, the command proceeds directly with that skill.
- If `--skill` matches nothing discovered, the command reports no match and exits.
- Telemetry is called only for the selected skills, not all skills in the repo.
- Previously installed skills do not have their status reset to `"pending"` unless they're genuinely new.

## Integration test requirements

- Running the command against a mocked `scanRepository` HTTP response (with `known: true`, matching commit, validation statuses) end to end:
  - Displays skills with their validation status badges
  - Allows user selection
  - Calls telemetry only for selected skills
  - Proceeds to platform selection and file write
- Verify that file content from backend response is available for SS-503's extraction step.
