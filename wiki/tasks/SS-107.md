# Catalog detail page (repo/skill view)

## Summary

Build the detail page for a validated repository or skill, reached by clicking a search result in the catalog (SS-104). The page displays: install instructions (CLI command), README content (from GitHub via backend), complete GitHub metadata (stars, contributors, issues, last updated — from SS-103's full enrichment), validation findings (if any), and a file tree preview showing the skill's structure. The route `loader` calls `@shared/firebase-cloude-api` to fetch the detail data, which includes both stored Firestore fields and live GitHub metadata merged together (per [FR-BE3](../requirements.md#fr-be3)). No component calls `fetch()` directly ([AD-4](../architecture-invariants.md#ad-4)).

## Unit test requirements

- The detail page renders all required sections: install command, README, GitHub metadata, validation status/findings, file tree.
- Given a detail payload with validation findings, both critical and non-critical findings are displayed in separate sections.
- Given a detail payload with no findings (clean validation), the page shows `"validated"` status with no issues listed.
- The install command is formatted correctly with the repo URL.
- An empty or missing README section renders a placeholder, not a broken layout.

## Integration test requirements

- The route's `loader` calls `@shared/firebase-cloude-api`'s detail function with the repo/skill ID and renders the merged response (Firestore + GitHub metadata).
- The full GitHub metadata enrichment (stars, contributors, issues) is displayed correctly.
