# GitHub metadata enrichment (catalog list + detail pages)

## Summary

Extend repository list and detail responses to blend stored Firestore fields with live GitHub API metadata, per [FR-BE3](../requirements.md#fr-be3).
Owned by a dedicated `functions/src/services/github-client.ts` — separate from the discovery logic
([AD-6](../architecture-invariants.md#ad-6): discovery returns files, this returns metadata only).

Two contexts with different data needs:
- **Catalog list view**: Lightweight enrichment (stars count, last updated date) for performance
- **Detail pages**: Full metadata (stars, contributors, issues, default branch, last updated)

The enrichment service accepts a context parameter to determine which fields to fetch from GitHub API.

## Unit test requirements

- The enrichment function with `context: 'list'` returns only stars and last updated date.
- The enrichment function with `context: 'detail'` returns full metadata (stars, contributors, issues, default branch, last updated).
- The enrichment function merges one stored repository record with a mocked GitHub API
  response into a single response object with both stored and live fields.
- A GitHub API failure for one repository doesn't fail the whole list — that repo's live
  fields are omitted/null while the rest of the list still returns.

## Integration test requirements

- Calling the list endpoint against the Firestore emulator with a stubbed GitHub API
  returns stored + lightweight live fields (stars, last updated) merged for every repository in the result.
- Calling the detail endpoint returns stored + full live metadata merged.
