# Favorites collection schema

## Summary

Define the `userFavorites` collection schema in `functions/src/services/user-favorites-store.ts`.
Document ID = userId (from Firebase Auth). Each user doc contains an array of favorites
(repoId + skillNames array where empty = all skills, non-empty = specific skills),
a `shareableLink` token for sharing, and timestamps ([AD-14](../architecture-invariants.md#ad-14)). This schema supports
[FR-UI9](../requirements.md#fr-ui9) (favorite repos/skills), [FR-UI10](../requirements.md#fr-ui10) (view favorites tab), [FR-UI11](../requirements.md#fr-ui11) (share link),
and [FR-UI12](../requirements.md#fr-ui12)/[FR-CLI10](../requirements.md#fr-cli10) (public access via link).

Schema:
```typescript
{
  userId: string,                   // Firebase Auth user ID
  favorites: Array<{
    repoId: string,                 // Reference to repositories/{repoId}
    skillNames: string[],           // Empty = all skills, specific names = partial
    addedAt: Timestamp
  }>,
  shareableLink: string,            // Generated token (SS-106)
  createdAt: Timestamp,
  updatedAt: Timestamp
}
```

## Unit test requirements

- The schema accepts a fully-populated payload with empty `skillNames` array (full repo).
- The schema accepts a payload with non-empty `skillNames` array (partial selection).
- The schema rejects a favorite missing `repoId` or with invalid `addedAt` timestamp.
- Server-side timestamp assignment overrides any client-supplied `created`/`updated`.

## Integration test requirements

- Writing a userFavorites doc via the store against the Firestore emulator persists
  every field including nested favorites array.
