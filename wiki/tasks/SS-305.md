# userFavorites store (backend)

## Summary

Implement `functions/src/services/user-favorites-store.ts` — the service layer that owns the
`userFavorites` collection ([AD-14](../architecture-invariants.md#ad-14)). Provides CRUD operations: create/update user favorites,
read by userId (auth-required per [AD-9](../architecture-invariants.md#ad-9)), and public read by `shareableLink` (no auth required —
[FR-UI12](../requirements.md#fr-ui12), [FR-CLI10](../requirements.md#fr-cli10)). HTTP adapters in `functions/src/functions/` wrap these calls.

**Operations:**
- `addFavorite(userId, repoId, skillNames)` — add or update a favorite entry
- `removeFavorite(userId, repoId)` — remove a favorite entry
- `getUserFavorites(userId)` — read favorites for a specific user (auth-required)
- `getFavoritesByLink(shareableLink)` — public read endpoint, returns favorites without auth

## Unit test requirements

- `addFavorite` creates a new favorites array if none exists, or appends to existing.
- `addFavorite` with empty `skillNames` array indicates full repo favorite.
- `removeFavorite` removes the correct entry from the favorites array.
- `getUserFavorites` returns the user's favorites array or empty if none exist.
- `getFavoritesByLink` returns favorites for a valid token, rejects invalid tokens.

## Integration test requirements

- Writing favorites via the store against the Firestore emulator persists the changes.
- Public read by link works without auth verification.
- Auth-required read rejects requests without valid Firebase ID token.
