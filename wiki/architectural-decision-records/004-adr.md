## ADR-4 — `shared/` is the only gateway to the backend and GitHub

**Status:** Accepted

**Context.** Two consumers (`client/` and `cli/`) both need to call the SkillStack
backend and the GitHub API. Letting each build its own `fetch` calls would scatter
URLs, auth headers, and error mapping across the codebase.

**Decision.** All outbound access lives in `shared/`, exposed under the `@shared`
alias and grouped by external system (`firebase-cloude-api/`, `github-api/`) plus
pure utilities. Consumers depend on intent (typed service functions), never on the
wire format. Neither `client/` nor `cli/` builds its own HTTP calls.

**Consequences.**

- A new backend capability means extending the gateway once, not editing every
  consumer.
- Transport concerns (base URLs, auth, error translation) are centralized and
  swappable.
- Invariant to preserve: adding a new integration adds a new group in `shared/`,
  not an inline call in a consumer.
